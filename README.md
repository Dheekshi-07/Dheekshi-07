## `05` — How I approach a problem

<p align="center">
  <img src="https://capsule-render.vercel.app/api?type=rect&height=3&color=0:38BDF8,50:2563EB,100:06B6D4" width="100%" alt="" />
</p>

```text
          ┌────────────────────────────┐
          │       DEFINE THE NEED      │
          │  Understand the real issue │
          └──────────────┬─────────────┘
                         ▼
          ┌────────────────────────────┐
          │      EXPLORE THE DATA      │
          │  Inspect inputs and limits │
          └──────────────┬─────────────┘
                         ▼
          ┌────────────────────────────┐
          │      DESIGN THE LOGIC      │
          │  Choose a practical method │
          └──────────────┬─────────────┘
                         ▼
          ┌────────────────────────────┐
          │      BUILD & TEST          │
          │  Check behaviour and edge  │
          │  cases before claiming     │
          └──────────────┬─────────────┘
                         ▼
          ┌────────────────────────────┐
          │      REFINE & LEARN        │
          │  Use evidence and feedback │
          └────────────────────────────┘
```

My principles:

- **Clarity over complexity** — solve the actual problem, not an imaginary bigger one.
- **Evidence over assumptions** — test behaviour and state limitations honestly.
- **Maintainability matters** — write code that another developer can understand.
- **Keep learning** — treat feedback and code reviews as part of engineering.
